# AMORÉTTO STANDARD 営業運用拡張 V5

## 目的

既存の正本、GUIDE、チェック、研修、スキル認定、ナレッジを変えずに、当日の営業・顧客履歴・記念日準備・在庫・正本改訂確認を一つの導線へ追加する。

## 追加機能

### 今日の営業

- 予約時間、名字、人数、座席、コースを当日表示
- 確認済みアレルギー、苦手食材、記念日、同伴の退店希望時刻を表示
- 同伴は料理完了を退店20分前、会計準備を10分前に表示
- ケーキ・花束の準備確認をスタッフが記録
- 日曜日のディナー前、木曜日の週末前に定期在庫確認を表示

### 店主管理

- 予約・顧客情報・営業履歴を年別に保存
- 予約状態と予約経路を記録
- 電話番号から過去履歴候補を表示し、店主確認後に同一顧客として関連付け
- アレルギー、好み、記念日履歴は参考表示に留め、今回分を自動確定しない
- 年度別または最大5年分をExcel（.xlsx）出力
- 5年経過後も自動削除せず、Excel保存確認後に店主が削除

### 正本強化

- 利用シーン11種
- 店主確認レベル0〜3
- 現場調整可・店主確認後・変更不可
- 基準の理由、優先順位、関連正本最大3件
- 6か月または12か月の見直し候補
- 重要改訂の確認済み記録

### 在庫

- 既存の在庫チェックから最大150項目へ初期化可能
- 基準数、発注点、現在数、状態、通常／至急
- 購入先、発注方法、連絡先、発注期限、入荷日数、発注単位
- スタッフは現在数、不足、緊急度、入荷確認数を記録
- 発注判断、注文済み、入荷待ち、入荷完了は店主のみ
- 自動発注と賞味期限管理は行わない

## 権限と個人情報

- 店主APIは既存のHttpOnly Cookie認証を必須とする
- スタッフAPIは既存スキル認定の端末ID・トークンを使用し、サーバー保存済みSHA-256ハッシュと照合する
- スタッフへ返す予約情報は名字と当日運用情報だけに限定する
- 電話番号、メールアドレス、フルネーム、過去履歴は店主画面だけで扱う
- スタッフ名はクライアント入力を信用せず、認証済みプロフィールから記録する

## 保存

既存の非公開Supabase Storage `amoretto-standard` の `operations/` 配下へ保存する。

- `settings.json`
- `reservations/YYYY.json`
- `inventory.json`
- `manual-meta.json`
- `important-updates.json`

## 互換性

- 既存の `config.json`、正本マニュアル、ナレッジ、スキル認定データは変更しない
- 新機能は `operations.js` の拡張レイヤーとして読み込む
- PWAキャッシュは `amoretto-standard-v11` へ更新する

## 検証

- `operations.js`、`app.js`、`service-worker.js` のJavaScript構文確認
- 生成したExcelを `openpyxl` で読み込み、シートとセル値を確認
- スタッフAPIは端末トークン未確認時に顧客・営業データを返さない
- Vercelプレビュービルド成功後に本番へ統合する
